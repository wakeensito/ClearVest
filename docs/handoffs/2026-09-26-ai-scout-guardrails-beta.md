## What changed

- Scout has an opening-only up/down/up scale reaction, popup-only green BETA, navy/yellow glass, and the one-line subtitle “A little clarity, whenever you need it.” The resting launcher has no badge. Existing pose and accessibility behavior remains.
- SAM defines finance/privacy and standalone portfolio-grounding guardrails, each with a published version. Advisor and Voice model permissions require the finance guardrail/version; ApplyGuardrail permission is resource-scoped. The bootstrap CD role gains tagged guardrail lifecycle permissions.
- Shared Converse always supplies a published guardrail. Input questions are screened/masked before new chat rows are saved. Policy interventions and unavailable checks never fall back to unguarded inference. Voice returns screened text; raw audio handling is unchanged.
- An explicit portfolio explanation runs single-turn source QA without conversation history or free-form goals. Grounding and relevance must both pass before the answer and expandable source receipt are shown. Ordinary chat carries no grounding claim. The API adds optional `grounded`, `userMessage`, `safety`, and `sources` fields; frontend types were regenerated.
- Added policy/integration tests, browser checks for source receipts and privacy persistence, and [an assessment/demo plan](../design/advisor-companion/scout-guardrails-and-demo.md) with [live evaluation cases](../design/advisor-companion/guardrail-eval-cases.json).

## Decisions & why

- AWS explicitly excludes conversational chat from contextual-grounding support. A separate source-QA action avoids certifying arbitrary chat. Source text is built server-side from saved holdings and computed risk; the reference carries its as-of date.
- Buy/sell/hold/allocation and guaranteed-return topics deny outputs while allowing educational input questions. Illegal financial instructions are denied in both directions. This allows useful reframing of “Should I put my savings in NVDA?” instead of requiring a refusal for every mention of a ticker.
- Grounding requests use `outputScope=FULL` so passing assessments are returned too. Both GROUNDING and RELEVANCE assessments must be present; missing/malformed results fail closed. No raw assessments or matched identifiers are logged by this integration.
- Published policy versions are used instead of DRAFT. Bump the corresponding GuardrailVersion Description whenever editing a policy; replacement publishes a new snapshot. IAM binds inference to that version.
- ApplyGuardrail has one attempt, 1s connect and 3s read. SAM uses one Nova attempt, 8s read for Advisor and 7s for Voice. Deadline checks preserve time for safety work; tight budgets produce unavailable responses rather than bypass checks.
- A source receipt is evidence of checks that ran, not a guarantee of correctness. Safety classifiers and PII detection need live false-positive/false-negative evaluation.
- Follow the user's instruction: no push until explicitly requested. This milestone remains uncommitted, and the existing draft PR was not updated.

## Gotchas

- Update the bootstrap deployment role before deploying the app. Required runtime variables are generated by SAM: `ADVISOR_GUARDRAIL_ID`, `ADVISOR_GUARDRAIL_VERSION`, `GROUNDING_GUARDRAIL_ID`, `GROUNDING_GUARDRAIL_VERSION` (the grounding pair is Advisor-only). Missing or DRAFT versions fail closed. Deploy frontend/backend together.
- Browser history now persists only screened text responses/questions. Older entries without screening metadata are not restored; voice turns currently remain session-only. Raw pending/failed input stays in memory, never newly persisted by ChatProvider.
- This is not a complete PII-retention migration. Existing server chat TTL, profile goals, uploaded audio, STT provider retention and account-level invocation logging remain separate boundaries. No historical data purge was performed.
- Ordinary chat can name a ticker present in the user's question for educational discussion, but cannot recommend a trade. It explicitly disclaims access to live news/prices. Grounded portfolio answers use no live news or inferred returns.
- General application demo identity remains a client-supplied UUID. Guardrails does not replace real authentication/authorization.
- WSL sandbox mounting fails in this environment; local commands used approved escalation. Windows Node/Chrome ran frontend tooling; Python tooling is under `/tmp/clearvest-venv`. SAM needs a Python-with-pip directory on PATH. The verified full build used `sam build --no-cached --build-dir /tmp/clearvest-scout-sam-build` with `/tmp/clearvest-venv/bin` on PATH. An earlier default build was stopped during slow NTFS dependency copying; rebuild or use the verified temporary template before any future deployment.
